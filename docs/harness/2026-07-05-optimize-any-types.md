## 执行摘要

通过 repo-lens 评分（loc=13193, internalDeps=3, recentCommits=1, anyCount=33）选中 `@coze/api` 包。实际扫描发现真实的显式 `any` 用法（排除注释与字符串）共 10 处，分布在 7 个文件：

- `src/fetcher.ts`：`adapterFetch` 的参数与返回值类型改为 `InternalAxiosRequestConfig` / `AxiosResponse`，node-fetch 的 `RequestInit` 通过独立变量声明后做窄化断言。
- `src/utils.ts`：
  - `mergeConfig` 改为泛型 `<T extends object>`，内部仍用 `Record<string, unknown>` 做安全的递归合并，调用方按需显式指定类型参数（`core.ts` 中两处分别指定 `FetchAPIOptions` / `WebsocketOptions`）。
  - `buildWebsocketUrl` 改为泛型 `<T extends object>`，不再要求调用方满足索引签名。
- `src/resources/files/files.ts`、`src/resources/audio/transcriptions/transcriptions.ts`、`src/resources/audio/voiceprint-groups/features.ts`：原先的 `file: File | any` 实际上要兼容浏览器 `File`/`Blob`、Node `fs.createReadStream()`、纯字符串路径与 uni-app 的 `{ filePath }` 描述符（已通过示例代码 `examples/coze-js-uniapp` 与 `examples/coze-js-node` 验证），因此在 `core.ts` 新增导出类型 `FileInput`，5 处引用统一收敛到该类型。
- `src/ws-tools/wavtools/lib/wav_recorder.ts`：`eventReceipts` 改为 `Record<number, unknown>`；私有方法 `_event` 改为泛型 `<T = unknown>`，`read()`/`save()`/`end()` 调用处按各自实际返回形状显式传入类型参数（新增 `ExportEventPayload` 类型描述 `export` 事件的 payload）。
- `src/ws-tools/utils/index.ts`：`setValueByPath` 的类型约束由 `Record<string, any>` 放宽为 `object`（内部仍安全转换为 `Record<string, unknown>` 操作），避免要求调用方类型必须显式声明索引签名。

修改过程中同步更新了两处受影响的测试用例类型标注（`test/fetcher.spec.ts`、`test/utils.spec.ts`），未改变任何运行时行为。
